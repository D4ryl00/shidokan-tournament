# Étape 4 : Moteur de tableaux et impressions — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** regrouper les inscriptions en **catégories**, générer pour chacune un tableau ou une poule selon les 7 formats de combat et le format kata (spec §11, §12), avec un tirage qui sépare les combattants d'un même club. Gérer le cycle de vie des catégories et imprimer les tableaux pour le gymnase.

**Architecture :**
- `src/domain/categories.ts` : clé « naturelle » d'une catégorie et regroupement des inscriptions.
- `src/domain/brackets/` : **moteur pur**.
  - `generateBracket(format, entrants, options, seed)` produit une structure de matchs **reliés entre eux** (le vainqueur ou le perdant d'un match alimente une case d'un autre match).
  - `resolveBracket(bracket, results)` remplit les cases d'après les résultats et calcule le **podium**. Cette fonction sert à tester chaque format dès maintenant ; l'étape 6 n'aura plus qu'à enregistrer les résultats.
  - Le kata a son propre modèle (passages notés).
- Côté serveur : table `categories`, `registrations.category_id`, synchronisation automatique des catégories non verrouillées, tableau stocké en JSON dans la catégorie.
- Côté interface : onglet « Tableaux », plus des pages d'impression (CSS `@media print`). Les PDF passent par l'impression de Chrome.

**Tech Stack :** inchangée.

**Spec :** §4.3 (catégorie), §11 (formats, options, génération, cycle de vie), §12 (kata, classement des poules), §13 (impressions), §13 bis (logo en en-tête des impressions).

## Global Constraints

- Toutes les contraintes précédentes s'appliquent.
- **Catégorie** = discipline + règlement + sexe + tranche d'âge + catégorie de poids. Pour le kata : discipline + sexe + tranche d'âge (spec §4.3). Une catégorie peut **réunir** plusieurs catégories de poids, d'âge ou de sexe : c'est le recasement de l'étape 5. Le modèle le permet dès maintenant, avec des listes.
- **Formats** : `single_match`, `best_of_three`, `round_robin`, `three_with_repechage`, `single_elimination`, `double_elimination`, `pools_then_bracket` pour le combat ; `kata_two_rounds` pour le kata.
- **Format par défaut selon le nombre** (spec §11.1, réglages) : `settings.formats.two` pour 2, `.three` pour 3, `.fourPlus` pour 4 et plus. Le kata utilise toujours `kata_two_rounds`. Une catégorie peut **imposer** son format.
- **Repêchage et combat pour la 3e place** : valeur de la compétition, modifiable par catégorie. **Repêchage désactivé par défaut**, 3e place désactivée (deux bronzes).
- **Tirage** : au sort, **en séparant les clubs** au premier tour autant que possible. Il est **reproductible** : la graine est stockée, et « Nouveau tirage » change la graine.
- **Cycle de vie** (spec §11.3) : `provisional` → `ready` → `started` → `finished`.
  - Toute modification (inscription, recasement, format) **régénère** les tableaux non lancés.
  - Une catégorie `started` est **verrouillée** ; la déverrouiller demande une confirmation.
- **Kata** (spec §12) :
  - tour 1 pour tous, puis finale à deux avec un 2e kata ;
  - 1er et 2e départagés par la **note de la finale seule** ;
  - note d'un passage : **moyenne simple s'il y a moins de 5 arbitres** ; à partir de 5, on retire la plus haute et la plus basse puis on fait la moyenne ;
  - bronzes : 3e (et 4e si `kataBronzeCount = 2`) du tour 1 ;
  - avec 2 compétiteurs, directement la finale.
- **Classement de poule** : victoires, puis confrontation directe, sinon **égalité signalée** : l'organisateur décide à l'étape 6.
- **Impression** : tableaux simples et lisibles de loin. Logo et nom de la compétition en en-tête ; **pas** de badges ni de motifs de recasement (spec §13).

## Review Focus

1. **Tailles limites** : 0, 1 (« sans adversaire », pas de tableau), 2, 3, 5, 6, 7, 9 et 17 combattants dans chaque format compatible. Exemples : exemptions (« byes ») en élimination directe, poules de taille inégale. Tests en Tasks 2 et 3.
2. **Repêchage FFK** : seuls ceux qui ont perdu contre l'un des deux finalistes sont repêchés, et les deux vainqueurs du repêchage sont 3es. Ça doit fonctionner même avec des exemptions. Test en Task 2.
3. **Séparation des clubs** : avec 8 combattants dont 4 du même club, aucun premier tour n'oppose deux combattants de ce club. Quand c'est impossible (5 sur 6), le nombre de rencontres entre clubmates est minimal. Test en Task 2.
4. **Régénération** : une inscription ajoutée ou supprimée régénère le tableau d'une catégorie `provisional` ou `ready`, **jamais** celui d'une catégorie `started`. Test en Task 4.
5. **Impression** : chaque catégorie sur sa page, lisible en noir et blanc, sans élément interactif. Vérification par capture PDF de Chrome en Task 6.

```ts
export type CombatFormat = 'single_match' | 'best_of_three' | 'round_robin' | 'three_with_repechage' | 'single_elimination' | 'double_elimination' | 'pools_then_bracket';
export type BracketFormat = CombatFormat | 'kata_two_rounds';
export interface Entrant { registrationId: string; clubId: string | null; label: string }
export type SlotSource =
  | { kind: 'entrant'; registrationId: string }
  | { kind: 'bye' }
  | { kind: 'winner' | 'loser'; matchId: string }
  | { kind: 'poolRank'; pool: number; rank: number } // poules puis tableau
  | { kind: 'empty' };
export type MatchPhase = 'main' | 'repechage' | 'third_place' | 'losers' | 'grand_final' | 'pool' | 'series';
export interface Match { id: string; phase: MatchPhase; round: number; order: number; a: SlotSource; b: SlotSource; pool?: number; optional?: boolean } // optional : 3e manche d'un meilleur des trois
export interface CombatBracket { kind: 'combat'; format: CombatFormat; entrants: Entrant[]; matches: Match[]; pools?: string[][]; options: { repechage: boolean; thirdPlace: boolean }; seed: number }
export type MatchMethod = 'points' | 'decision' | 'ko' | 'abandon' | 'disqualification' | 'forfeit';
export interface MatchResult { winner: 'a' | 'b'; method: MatchMethod; score?: string }
export interface ResolvedMatch extends Match { entrantA: string | null; entrantB: string | null; result: MatchResult | null; playable: boolean; bye: boolean }
export interface Podium { first: string | null; second: string | null; thirds: string[]; complete: boolean; ties: string[][] } // ties : égalités à trancher (poules)
// seeding.ts
export function seededRandom(seed: number): () => number;                     // mulberry32
export function drawOrder(entrants: Entrant[], seed: number): Entrant[];       // mélange puis répartition par club (clubs les plus nombreux d'abord, en alternance)
export function bracketPositions(size: number): number[];                     // ordre de placement standard (1, 16, 9, 8, 5, 12, 13, 4, …) en 0-based, size = puissance de 2
// elimination.ts
export function singleElimination(entrants: Entrant[], options: { repechage: boolean; thirdPlace: boolean }, seed: number): CombatBracket;
export function doubleElimination(entrants: Entrant[], seed: number): CombatBracket;
// index.ts
export function resolveBracket(bracket: CombatBracket, results: Record<string, MatchResult>, tieBreaks?: Record<number, string[]>): { matches: ResolvedMatch[]; podium: Podium };
```

  Règles d'élimination directe :
  - taille = puissance de 2 supérieure ou égale ;
  - exemptions placées en face des **premiers** de l'ordre de tirage. Un match contre une exemption n'est **pas jouable** : son vainqueur avance automatiquement ;
  - 3e place (option) : match entre les perdants des demi-finales ;
  - **repêchage** (option, spec §11.1 et FFK) : pour chaque finaliste, les combattants qu'il a battus **avant la finale**, dans l'ordre des tours, s'affrontent en chaîne (le perdant du 1er tour contre celui du 2e, le vainqueur contre celui du tour suivant, etc.). Le vainqueur de chaque chaîne est 3e. Les cases du repêchage pointent sur les matchs du tableau principal (`loser`) ; le moteur les remplit quand les finalistes sont connus ;
  - sans 3e place ni repêchage : les deux perdants des demi-finales sont 3es ;
  - **2 combattants** → un seul match (finale) ; **1** → pas de tableau ; **0** → vide.

  Double élimination : tableau des gagnants, tableau des perdants (reprise classique), grande finale unique sans revanche. Le 3e est le perdant de la finale du tableau des perdants.

- [ ] **Step 1 : Tests de tirage.**
  - `seededRandom(42)` est reproductible.
  - `bracketPositions(8)` vaut `[0, 7, 4, 3, 2, 5, 6, 1]`, ou tout ordre standard où les têtes 1 et 2 sont dans des moitiés opposées. Tester les propriétés : 1 et 2 dans deux moitiés différentes, 1 à 4 dans quatre quarts différents.
  - **Séparation des clubs** : 8 combattants dont 4 du club A et 4 de clubs différents → `singleElimination` n'a **aucun** match du 1er tour entre deux A. 6 combattants dont 5 du club A → au plus 2 matchs A contre A au 1er tour, compte tenu des exemptions.
- [ ] **Step 2 : Tests d'élimination directe**, avec un helper `play(bracket, winnersByMatchOrder)` qui fait gagner le côté `a` par défaut.
  - Tailles 2, 3, 5, 8, 9 et 17 : nombre de matchs jouables, exemptions non jouables, podium complet après tous les résultats.
  - 3 combattants : une exemption ; podium 1er, 2e, un seul 3e.
  - 3e place activée sur 8 → un match `third_place` ; le podium a un seul 3e.
  - **Repêchage** sur 8 (A bat B au 1er tour, A bat C en demi, A finaliste ; D bat E, D bat F, D finaliste) → matchs de repêchage B–C (puis rien) côté A, E–F côté D ; podium avec 2 troisièmes : les vainqueurs des repêchages. Sur 5 avec exemptions : la chaîne ignore les exemptions.
  - Repêchage **et** 3e place activés → le repêchage l'emporte (pas de match de 3e place). Consigner une ruling.
  - Double élimination sur 4 et 6 : chaque combattant peut perdre une fois avant d'être éliminé ; podium complet.
  - 1 combattant → `matches: []` ; podium `first` = ce combattant, `complete: true`.
