# Étape 9 : Zones de combat nommées — plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** le « nombre de tatamis » devient une liste de zones de combat nommées (« Tatami 1 », « Ring »…) et ordonnées ; les catégories sont affectées à une zone ; le nom de la zone est imprimé sur les tableaux.

**Architecture:** nouvelle table `zones` (une ligne par zone, par compétition) ; `categories.zone_id` remplace `categories.tatami` ; la migration reprend les tatamis existants sous les noms « Tatami 1 » à « Tatami N » et garde l'affectation des catégories. L'API expose la liste des zones (lecture, remplacement) ; l'écran Combats et le programme se groupent par zone.

**Tech Stack:** TypeScript, Drizzle (SQLite, migration écrite à la main pour la reprise des données), Fastify, React 19 + Mantine 8, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-22-ordre-de-passage-et-aides-design.md` §1.2 (zones de combat) ; les étapes suivantes (vagues, ordre de passage) s'appuieront sur ces zones.

## Global Constraints
- Une zone : `id` (texte), `name` (libre, non vide, 40 caractères au plus, unique dans la compétition sans tenir compte de la casse ni des accents), `order` (ordre d'affichage). Une compétition a **au moins une zone**.
- Création d'une compétition : « Nombre de zones de combat » (1 à 20, défaut 2) crée « Tatami 1 » … « Tatami N ».
- Compétitions existantes : leurs `tatami_count` tatamis deviennent « Tatami 1 » … « Tatami N » ; une catégorie affectée au tatami k est affectée à la zone « Tatami k ».
- Supprimer une zone retire l'affectation de ses catégories (elles passent « Sans zone ») ; c'est **refusé (409)** si une de ses catégories est lancée ou terminée.
- Le nom de la zone figure sur chaque tableau imprimé et sur les feuilles de résultats (« Zone : Tatami 1 ») ; rien si la catégorie n'a pas de zone.
- Vocabulaire de l'interface : « zone de combat » / « zone » (plus « tatami » comme notion générique) ; aides (`src/web/help.ts`) mises à jour.
- Tous les tests restent verts : `npm run typecheck && npm test && npm run test:e2e`.

## Review Focus
- **Base existante** : une base créée avant l'étape 9 (tatamis 1 et 2, catégories affectées) doit se migrer sans perte — test Task 1 (base au niveau de la migration 0007, puis ouverture).
- **Renommer une zone** ne change pas l'affectation des catégories (identifiant stable) — test Task 1.
- **Deux zones de même nom** (« Ring » / « ring ») refusées — test Task 1.
- **Zone supprimée pendant la compétition** avec une catégorie lancée : refus clair — test Task 1.
- **Restauration d'une sauvegarde** : la table `zones` est copiée comme les autres (copie de toutes les tables) — test Task 1.

  ```sql
  -- après CREATE TABLE zones et ALTER TABLE categories ADD zone_id :
  WITH RECURSIVE n(k) AS (SELECT 1 UNION ALL SELECT k + 1 FROM n WHERE k < 20)
  INSERT INTO zones (id, competition_id, name, sort_order)
    SELECT c.id || ':z' || n.k, c.id, 'Tatami ' || n.k, n.k - 1 FROM competitions c JOIN n ON n.k <= c.tatami_count;
  UPDATE categories SET zone_id = competition_id || ':z' || tatami WHERE tatami IS NOT NULL
    AND EXISTS (SELECT 1 FROM zones z WHERE z.id = categories.competition_id || ':z' || categories.tatami);

  ```
