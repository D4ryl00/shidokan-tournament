# Étape 1 : Socle — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** Une app TypeScript lancée via Docker, où l'on crée une compétition, règle ses paramètres et modifie sa grille âge/poids (FFK par défaut), avec thèmes clair et sombre, logo Shidokan France, et tests d'interface sur Chrome.

**Architecture :** un seul paquet npm, trois couches.
- `src/domain` : logique métier pure, sans entrée/sortie : grille FFK, poids, âges, réglages.
- `src/server` : Fastify, Drizzle ORM sur SQLite. Il sert l'API `/api/*` et l'interface compilée.
- `src/web` : React, Vite et Mantine.

Les schémas Zod partagés vivent dans `src/domain`, importés à la fois par le serveur et par l'interface.

**Tech Stack :**
- Node.js 22 LTS, TypeScript (strict, ESM) ;
- Fastify 5, `@fastify/static` ;
- Drizzle ORM + drizzle-kit, better-sqlite3 ;
- Zod ;
- React 19, Vite 6, Mantine 8 (`@mantine/core`, `@mantine/hooks`, `@mantine/notifications`), react-router 7, TanStack Query 5 ;
- Vitest, Playwright (canal `chrome`) ;
- Docker / Docker Compose.

**Spec :** `docs/superpowers/specs/2026-10-21-tableaux-shidokan-design.md` (§4.3, §9.2, §13 bis, §14, §15, §17). Feuille de route : `docs/superpowers/plans/2026-10-21-00-feuille-de-route.md`.

## Global Constraints

- **Interface entièrement en français**, y compris les messages d'erreur renvoyés par l'API.
- **100 % hors ligne** : aucune requête à l'exécution vers un CDN, une police ou un service externe.
- **Chrome** est le navigateur de référence : les tests e2e tournent avec Playwright, `channel: 'chrome'`.
- **Thème clair et sombre**. Par défaut, celui du système ; le choix forcé est mémorisé dans `localStorage`, clé `shidokan-color-scheme`.
- **Logo** : `assets/brand/shidokan-france-logo.webp` (512 × 512, transparent). En thème sombre, il est posé sur un **disque blanc** (`#ffffff`). Le SVG d'origine n'est pas utilisé.
- **`src/domain` n'importe rien** de `src/server`, de `src/web`, ni de modules Node d'entrée/sortie.
- **Accès base uniquement via l'API Drizzle**, sans SQL brut hors des migrations générées : le passage futur à PostgreSQL doit rester possible.
- Chemin de la base : variable `DATABASE_PATH`, par défaut `./data/shidokan.sqlite`. Port : `PORT`, par défaut `3000`. Hôte : `0.0.0.0`.
- **`coupe-shidokan.xlsx` n'est jamais commité** (données personnelles).

## Review Focus

1. **Accents et caractères français** (« Coupe Shidokan – Côte d'Azur ») : ils doivent faire l'aller-retour intact entre l'interface, l'API et SQLite. Test en Task 5.
2. **Redémarrage du serveur ou du conteneur** : les compétitions sont toujours là après redémarrage sur la même base. Test en Task 4, vérification en Task 9.
3. **Réglages invalides** (seuil négatif, tolérance de 50 kg, nombre de tatamis à 0) : l'API répond 400 avec un message en français, et rien n'est enregistré. Test en Task 5.
4. **Libellés de poids variés** (« -35 », « +84 », « 84+ », « -35 kg », « 35 kg et + », nombre `-35`) : ils doivent tous être compris pareil. Tests en Task 3.
5. **Logo en thème sombre** : il ne doit jamais apparaître noir sur fond sombre. Le conteneur du logo a un fond `rgb(255, 255, 255)` en sombre. Test en Task 8.
