# Étape 6 : Jour J — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** dérouler la compétition depuis le PC central :
- affecter les catégories aux tatamis et afficher les prochains combats ;
- saisir les résultats (vainqueur, méthode, score) avec avancement automatique et correction ;
- trancher les égalités (poules, kata) et saisir les notes de kata ;
- imprimer les **feuilles de résultats** (tableaux remplis) ;
- exporter les **podiums** et le **classement des clubs** (PDF par l'impression, .ods et .xlsx) ;
- **sauvegarder automatiquement** la base et la restaurer ;
- enregistrer une grille comme **modèle**.

**Architecture :**
- `src/domain/results.ts` (pur) : filtrage des résultats encore valides (un résultat mémorise ses deux combattants et est **ignoré** si le tableau a changé, cf. relecture de l'étape 4), combats touchés par une correction, état d'une catégorie (lancée, terminée), tableau des médailles.
- Le serveur stocke résultats, notes de kata et départages, passe une catégorie en `started` au premier résultat et en `finished` quand son podium est complet, fait les exports (SheetJS), les sauvegardes (`VACUUM INTO`) et la restauration.
- L'interface ajoute les onglets « Combats » (tatamis, saisie, kata) et « Podiums » (podiums, médailles, exports, sauvegardes).

**Spec :** §12 (déroulé, résultats, classement des poules, kata), §13 (feuilles de résultats = tableaux remplis, podiums, classement des clubs, sauvegarde), §15 (sauvegarde automatique, journal), §4.3 (modèles de grille).

## Global Constraints

- Toutes les contraintes précédentes s'appliquent.
- **Méthodes de victoire** (spec §12) : `points`, `decision`, `ko` (**shobu uniquement**), `abandon`, `disqualification`, `forfeit`. Le score est facultatif.
- **Un résultat mémorise ses deux combattants**. Si le tableau a été régénéré ou modifié depuis (combattants différents dans ce match), le résultat est **ignoré** et signalé : jamais appliqué à d'autres combattants.
- **Correction** d'un résultat déjà saisi : autorisée ; les combats suivants touchés (dont les résultats ne sont plus cohérents) sont **signalés**, et leurs résultats deviennent invalides par la règle précédente.
- **Cycle de vie** : premier résultat → `started` (verrouillage, étape 4) ; podium complet → `finished` ; suppression du dernier résultat → retour à `ready`.
- **Kata** (spec §12) :
  - notes sur 10, nombre d'arbitres variable ;
  - moins de 5 arbitres : moyenne ; 5 et plus : sans la plus haute ni la plus basse ;
  - 1er et 2e départagés par la finale seule ;
  - bronzes = 3e (et 4e) du tour 1 ;
  - égalités tranchées par l'organisateur.
- **Classement des poules** : victoires, confrontation directe, sinon décision de l'organisateur (`tieBreaks`).
- **Classement des clubs** : par médailles d'or, puis d'argent, puis de bronze, puis nom.
- **Feuilles de résultats** = tableaux de combat **remplis**, au même format que l'impression de l'étape 4 (spec §13), sans badges.
- **Sauvegarde automatique** : copie cohérente (`VACUUM INTO`) toutes les `BACKUP_INTERVAL_MIN` minutes (par défaut 5) dans `<dossier de la base>/sauvegardes/`, en gardant les 30 dernières. Une sauvegarde manuelle est téléchargeable. La **restauration** exige une confirmation.

## Review Focus

1. **Résultat périmé** : saisir un résultat, déverrouiller la catégorie, ajouter un combattant, régénérer → l'ancien résultat n'est jamais appliqué au nouveau tableau, et il est listé comme « résultat ignoré ». Test en Task 2.
2. **Correction en chaîne** : corriger le vainqueur d'un quart alors que la demie est jouée → la demie est signalée « à revoir », son résultat est ignoré, le podium n'est plus complet. Tests en Tasks 1 et 2.
3. **KO en jiyu** refusé ; résultat sur un combat non jouable (exemption, combattants inconnus) refusé. Test en Task 2.
4. **Restauration** d'une sauvegarde : l'état revient exactement ; un fichier qui n'est pas une base de l'app est refusé sans rien casser. Test en Task 3.
5. **Égalité de poule à trois et égalité de kata** : le podium reste incomplet tant que l'organisateur n'a pas tranché, puis il est complet. Tests en Tasks 1 et 2.

### Task 1 : Domaine — résultats, corrections, état, médailles, départage kata

**Interfaces :**

```ts
// results.ts
export interface ResultRecord { matchId: string; winner: 'a' | 'b'; method: MatchMethod; score?: string; entrantA: string; entrantB: string }
export function validResults(bracket: CombatBracket, records: ResultRecord[], tieBreaks?: Record<number, string[]>): { results: Record<string, MatchResult>; ignored: ResultRecord[] }; // résolution progressive : un enregistrement ne compte que si ses combattants correspondent à ceux du match
export function affectedBy(bracket: CombatBracket, records: ResultRecord[], matchId: string, newWinner: 'a' | 'b'): string[]; // matchs (déjà joués) dont le résultat deviendrait ignoré
export function checkResult(match: ResolvedMatch, ruleset: Ruleset | null, method: MatchMethod): string | null; // erreur FR : match non jouable, KO hors shobu
export type CategoryProgress = { status: 'not_started' | 'started' | 'finished'; played: number; total: number; podium: Podium; ignored: number };
export function categoryProgress(bracket: Bracket, records: ResultRecord[], kataScores: KataScores | null, tieBreaks: Record<number, string[]>, kataTieBreak?: string[]): CategoryProgress;
export interface MedalRow { clubId: string | null; club: string; gold: number; silver: number; bronze: number }
export function medalTable(podiums: { podium: Podium }[], clubOf: (registrationId: string) => { id: string | null; name: string }): MedalRow[];
// kata.ts
export function resolveKata(b: KataBracket, scores: KataScores, tieBreak?: string[]): …;   // tieBreak : ordre imposé pour les ex-æquo (tour 1 et finale)
```

### Task 2 : Serveur — résultats, kata, départages, tatamis, podiums, exports

**Interfaces :**
- Tables :
  - `match_results` : competition_id, category_id, match_id, winner, method, score, entrant_a, entrant_b, created_at ; clé (category_id, match_id) ;
  - `kata_scores` : category_id, registration_id, round (`round1`|`final`), notes_json ; clé (category_id, registration_id, round) ;
  - `tie_breaks` : category_id, scope (`pool:<n>` | `kata`), order_json ; clé (category_id, scope).
- Routes (préfixe `/api/competitions/:id`) :

| Méthode | Route | Rôle |
|---|---|---|
| GET | `/categories/:cid/results` | `{ records, ignored, progress, kataScores, tieBreaks }` |
| PUT | `/categories/:cid/results/:matchId` | `{ winner, method, score? }` → contrôle (`checkResult`), enregistre avec les combattants du match, met le statut à jour (`started` / `finished`) ; renvoie `{ affected: string[] }` (combats suivants touchés) |
| DELETE | `/categories/:cid/results/:matchId` | efface ; plus aucun résultat → `ready` |
| PUT | `/categories/:cid/kata/:registrationId/:round` | `{ notes: number[] }` (0 à 10, au plus 7 notes) |
| PUT | `/categories/:cid/tie-break` | `{ scope, order: string[] }` |
| PATCH | `/categories/:cid` | (existant) `tatami`, plus `order` (rang de passage sur le tatami) |
| GET | `/schedule` | `{ tatamis: { tatami: number, categories: { id, label, status, nextMatches: { matchId, number, a, b }[] }[] }[], unassigned: [...] }` |
| GET | `/podiums` | `{ categories: { id, label, podium, complete }[], medals: MedalRow[] }` |
| GET | `/exports/results.(ods\|xlsx)` | tous les combats : catégorie, n°, combattants, clubs, vainqueur, méthode, score |
| GET | `/exports/podiums.(ods\|xlsx)` | feuille « Podiums » + feuille « Clubs » (médailles) |

- La synchronisation (étape 4) ne régénère jamais une catégorie lancée ; le déverrouillage garde les résultats, qui seront ignorés s'ils ne correspondent plus.
